# F19 — fix ticket: settle-window write verification (the SMC updates `F0Tg` on a ~1 s tick) + doctor stale-binary check

Fixing the **third** timing-model defect found on real hardware, now with measurements. Read `DESIGN.md`
first (BINDING, see RULING F19), then `PRD.md` §6.R1 / §6.R4, then this card.

## What the hardware actually does (measured, 2026-09-14 20:47 IST, this machine)

Register map (from `drivers/hwmon/applesmc.c`, the authority): `fan1_input` = `F0Ac` (actual, RO),
`fan1_output` = `F0Tg` (**target, RW**), `fan1_manual` = bit 0 of the `FS!` 16-bit mask,
`fan1_min/max` = `F0Mn`/`F0Mx`.

```
20:47:09  manual=0  target=6688  actual=6640     <- SMC auto: target tracks actual
20:47:10  manual=1  target=6688  actual=6654     <- manual armed; target unchanged
20:47:11  manual=1  target=2000  actual=5875     <- our write was taken (<= 1 s)
20:47:12  manual=1  target=2000  actual=2664
20:47:13  manual=1  target=2000  actual=1632
20:47:14  manual=1  target=2000  actual=1940
20:47:15  manual=1  target=2000  actual=2044
20:47:19  manual=1  target=2000  actual=2001     <- settled ~5 s, +/-20 rpm
20:47:27  manual=0  target=6229  actual=4780     <- auto restored, SMC takes over
```

So: **writes are honored, the echo is real, and the SMC adopts `F0Tg` asynchronously on a ~1 s tick.**
F16's verification is therefore wrong on *timing*, not on principle: `VERIFY_ATTEMPTS = 3` retries fire
microseconds apart inside one poll, read the not-yet-ticked register, conclude "write not taken" three
times, and after `WRITE_FAIL_FALLBACK` polls the daemon hands the fan back and latches monitor-only.
The same applies to `set_mode` (the `FS!` write is likewise asynchronous).

Note for context (ledger has the full story): the 20:36 failure the user hit was the **stale F14
binary** — the daemon had not been restarted after the F16/F18 install. F16's echo check had never run
on hardware before your change. Do not "fix" by reintroducing a tach comparison; the tach is not a
verification source (RULING F16 stands).

## RULING F19 (frozen — implement exactly; `DESIGN.md` amended by the orchestrator)

- **R1 — settle-window verification.** `SysfsSmc::write_speed` writes the target **once**, then polls the
  `fan1_output` echo until it matches (`WRITE_ECHO_TOLERANCE_RPM = 50`) or the window expires:
  `ECHO_SETTLE_MS = 1500`, sampled 10 × 150 ms. Accept on the first match. Only if the window expires
  without a match may the write be re-issued once (single retry, then its own window); after that
  `SmcError::VerifyFailed`. Total worst case ≤ ~3 s. Rationale: the register is the truth, but it ticks
  on the SMC's clock, not ours.
- **R2 — same treatment for `set_mode`.** The `fan1_manual` write is verified inside an equivalent
  settle window (`MODE_SETTLE_MS = 1000`, exact match on the 0/1 bit); only then is it a failure.
- **R3 — no microsecond hammering.** Remove the microsecond-spaced retry ladder entirely. A write storm
  against the SMC's control task is both pointless and impolite; one write per window.
- **R4 — L1, stall detector, dynamics from F16/F16a stand unchanged.** `VERIFY_TOLERANCE_RPM = 150`
  remains the steady-state tracking band; `STALL_POLLS = 10` remains the "actuator really is not
  responding" net (the measured ~5 s full-swing convergence fits inside it comfortably).
- **R5 — the mock must model the latency.** `MockSmc` gains `set_echo_latency(Duration)` (the target is
  adopted only after that much simulated time / N reads). Its tach-lag default should reflect the
  measured dynamics (~3000 rpm/s down, ~2000 rpm/s up, ~5 s to settle, small overshoot) rather than the
  idealized sketch. This is the regression the hardware found; it must be a test.
- **R6 — `doctor` gains a stale-binary check.** Compare the unit's `ExecMainStartTimestamp` with the
  mtime of the running binary (`/proc/<MainPID>/exe`, falling back to `/usr/bin/afanctl`); if the daemon
  started *before* the installed binary was last modified ⇒ `WARN — running daemon predates the
  installed binary — restart the unit (systemctl restart afanctl)`. This exact confusion cost a
  hardware round: a fresh package install without a restart silently keeps testing the old build.

## CONVENTIONS (verbatim from DESIGN.md §8 — binding)

> This is a byte-faithful copy of PRD §8 as of plan time. If PRD §8 and this copy ever diverge, the PRD wins and the orchestrator re-renders from the PRD.

**Language & toolchain**
- Rust edition 2021; rustc 1.98 (Arch `extra/rust`; install via `sudo pacman -S rust` — or `pkexec --disable-internal-agent pacman -S rust` on this box).
- No async. No threads beyond the main loop (single-threaded design; `Send` bound on `Smc` is for the trait's future, not for spawning).
- Dependencies: allowlist in R11 only. Adding one = stop, record in `DEVIATIONS.md`, await planner.

**Correctness discipline**
- No `unwrap`/`expect`/`panic!` outside tests, `main.rs` wiring, and `safety.rs`'s deliberate test panic. Clippy denies them (`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` — allowlisted per-file where required).
- `unsafe` only in `safety.rs`, each block carrying a `// SAFETY:` comment naming the async-signal-safety argument.
- Every state-changing `smc` write goes through write-verify (R1). Never update logical state from an unverified write (the `mbpfan.c:410` class).
- Temps are `MilliC`, never bare `i32` across module boundaries. rpm are `u32`.

**Style**
- `cargo fmt` default config, no customization. `//!` module doc on every file stating its contract and invariants in ≤10 lines. Public items get doc comments. Safety-critical lines get `// SAFETY:` or `// INVARIANT:` comments.
- Errors: per-module `thiserror` enum; error messages name the path/key and the fix. Logging via `tracing` macros only — no `println!` outside `cli.rs` output formatting.
- Tests: unit tests co-located (`#[cfg(test)]`); cross-module tests in `tests/`. Every behavioral claim in this PRD that is testable on fixtures/mocks **must** have a test (see R10 list).

**Safety of the build process itself (non-negotiable)**
- **Never write to the real `/sys` during development.** All tests run against `tests/fixtures/sysfs/` via `--sysfs-root`. Real-hardware tests run only behind `--features hw` + `AFANCTL_HWTEST=1` + applesmc present, and only in the final supervised gate (§9). If a test would write real sysfs without those guards, that test is a bug.
- Never run the daemon against real hardware as part of ordinary development; the supervised gate does that, with the user present.
