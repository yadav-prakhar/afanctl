# F25 — fix ticket: `doctor` must report the daemon's mode (PRD §9.3g requires "warns hold active"; it never reads the runtime state at all)

Found during the supervised hardware gate, step (g). Read `DESIGN.md` (BINDING), `PRD.md` §6.R5 (the
doctor check list) and §9.3g, then this card.

## The gap

PRD §9.3g says: *"`afanctl hold 3000` from a user shell via the polkit rule — fan goes to ~3000, `doctor`
**warns hold active**, ..."*.

Verified in source: `doctor` never consults the runtime state at all — there is no read of
`state.json`/`cmd.json` anywhere in `src/doctor.rs` (grep: zero hits), and no check touches the daemon's
mode. On the hardware gate, `hold 3000` worked (fan reached 2980 rpm, `status` showed `mode: hold`,
`target: 3000`, `manual: true`) but `doctor` said nothing about it: a user running `doctor` while a hold
is in force — or while the daemon is degraded — gets nine green checks and no hint that the fan is being
driven manually or that writing has been latched off.

## RULING F25 (implement exactly)

Add **one** new check to `doctor`'s list, placed after the existing `systemd unit health` /
`running daemon matches installed binary` pair:

- **`daemon mode`**
  - Read the daemon's runtime state exactly the way `status` does (resolve the same runtime directory —
    respect `AFANCTL_RUNTIME_DIR`, default `/run/afanctl` — and read `state.json`; do **not** add new
    path constants outside the module that already owns them; reuse whatever `cli.rs`/`supervisor.rs`
    expose, and if nothing is reusable, keep the one new constant inside `doctor.rs` with a comment).
  - No state file / unreadable ⇒ `PASS — daemon mode — no running daemon (observe is the default)`
    (doctor must stay useful on a machine where the unit is not running).
  - `mode: "hold"` ⇒ **`WARN`**, detail naming the held rpm and that the hold is a manual command: e.g.
    `hold active (3000 rpm, manual=true) — overshoot guard still applies; release with \`afanctl observe\``.
  - `mode: "curve"` ⇒ `PASS` (name it).
  - `mode: "observe"` ⇒ `PASS`.
  - `monitor_only: true` **or** `auto_restore_pending: true` ⇒ escalate the line to **`WARN`** (not FAIL)
    with the flag(s) and, if `recent_errors` is non-empty, the newest message — this is the diagnostic a
    user needs *precisely* when the daemon is not controlling. `monitor_only` outranks `mode` in the
    message text: the state is "requested X, writing nothing".
  - Unknown/missing `mode` field ⇒ `WARN` naming the raw value.
- `--json` output must carry the same fields as the human line (Appendix C's rule: the JSON reuses the
  human fields) — no schema-id change, no new top-level keys beyond the checker's existing shape.
- A `WARN` must **not** change doctor's exit code (only `FAIL` does — R5/Appendix C).

## CONVENTIONS (verbatim from DESIGN.md §8 — binding)

> This is a byte-faithful copy of PRD §8 as of plan time. If PRD §8 and this copy ever diverge, the PRD wins and the orchestrator re-renders from the PRD.

**Language & toolchain**
- Rust edition 2021; rustc 1.98 (Arch `extra/rust`; install via `sudo pacman -S rust` — or `pkexec --disable-internal-agent pacman -S rust` on this box).
- No async. No threads beyond the main loop (single-threaded design; `Send` bound on `Smc` is for the trait's future, not for spawning).
- Dependencies: allowlist in R11 only. Adding one = stop, record in `DEVIATIONS.md`, await planner.

**Correctness discipline**
- No `unwrap`/`expect`/`panic!` outside tests, `main.rs` wiring, and `safety.rs`'s deliberate test panic. Clippy denies them (`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` — allowlisted per-file where required).
- `unsafe` only in `safety.rs`, each block carrying a `// SAFETY:` comment naming the async-signal-safety argument.
- Every state-changing `smc` write goes through write-verify (R1). Never update logical state from an unverified write (the `mbpfan.c:410` class).
- Temps are `MilliC`, never bare `i32` across module boundaries. rpm are `u32`.

**Style**
- `cargo fmt` default config, no customization. `//!` module doc on every file stating its contract and invariants in ≤10 lines. Public items get doc comments. Safety-critical lines get `// SAFETY:` or `// INVARIANT:` comments.
- Errors: per-module `thiserror` enum; error messages name the path/key and the fix. Logging via `tracing` macros only — no `println!` outside `cli.rs` output formatting.
- Tests: unit tests co-located (`#[cfg(test)]`); cross-module tests in `tests/`. Every behavioral claim in this PRD that is testable on fixtures/mocks **must** have a test (see R10 list).

**Safety of the build process itself (non-negotiable)**
- **Never write to the real `/sys` during development.** All tests run against `tests/fixtures/sysfs/` via `--sysfs-root`. Real-hardware tests run only behind `--features hw` + `AFANCTL_HWTEST=1` + applesmc present, and only in the final supervised gate (§9). If a test would write real sysfs without those guards, that test is a bug.
- Never run the daemon against real hardware as part of ordinary development; the supervised gate does that, with the user present.

- Ambiguity or a blocking question → write it to `QUESTIONS.md`, continue with the unambiguous remainder, and say so in your summary. Do not invent spec.
