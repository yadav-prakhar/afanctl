# F14 — fix ticket: startup reconcile (stale manual state) + startup evidence line

You are fixing a **safety defect found on real hardware during the supervised gate**. Read
`DESIGN.md` first (BINDING), then `PRD.md` §6.R3/R4, §9.3, then this card.

## The defect

`Supervisor::run()` arms L2, notifies READY and enters the poll loop **without ever looking at
the fan's current mode**. L2 covers only catchable signals (panic hook + raw
`SIGSEGV/SIGABRT/SIGTERM/SIGINT` handlers). A **SIGKILL** — `kill -9`, OOM-kill, cgroup kill —
cannot be caught, so the process dies with `fan1_manual == 1` and the SMC safety net disabled.
systemd then restarts the unit with `ExecStart=/usr/bin/afanctl daemon --mode observe`, and
observe mode writes nothing by design (R3), so **nothing ever restores AUTO**: the fan stays in
manual mode at the last commanded speed, indefinitely and silently. That is mbpfan's C1 defect
class — the exact failure this project exists to make impossible.

PRD §9.3e asserts "L2 already restored AUTO" after a SIGKILL; that mechanism is physically
impossible for an uncatchable signal. The *property* PRD §9.3e demands is right, the named
mechanism is wrong. The observable guarantee must become: **AUTO within ~1 s of the restart.**

## Design ruling (FROZEN — implement exactly; already amended in `DESIGN.md`)

Startup order in `run()` becomes:

1. arm L2 (`install_death_path`) — unchanged, must stay first;
2. **reconcile stale state** (new);
3. `sd_status` + `sd_ready` — unchanged;
4. poll loop — unchanged.

### 2 — reconcile (new)

- Read the fan via `self.smc.read_fan()`.
- `FanMode::Manual` ⇒ log loudly (warn: the previous process died without restoring AUTO — an
  `error!` is optional but the message MUST name the cause and the action) → restore AUTO with
  `self.smc.set_mode(FanMode::Auto)` on the **verified write path**, and record it with
  `note_recent` so `status --json` / the plugin see it.
- If that restore **fails**: log the error, set `monitor_only = true` and force
  `mode = RunMode::Observe`. INVARIANT: never command manual mode while AUTO cannot be restored
  (fail-toward-AUTO, R4).
- If `read_fan()` **fails**: cannot confirm the fan state ⇒ treat exactly like a failed restore
  (degrade to observe + `monitor_only`) when the commanded mode writes; in observe it is a warn.
- `FanMode::Auto` ⇒ nothing written (reconcile is idempotent; no write on the healthy path).

This also cleans up a stale manual state left by anything else (an old `mbpfan`, a killed
`doctor --roundtrip`) — that is a bonus, not the reason.

### Startup evidence line (same fix, observability)

Add exactly one `tracing::info!` at startup naming: effective mode, L2 armed (yes/no), watchdog
notify path present (yes/no), config source path, and hw band. Reason: §9.3d asks the user to see
READY + watchdog in the journal, and today the journal carries **only** systemd's lines — the
application is silent until something goes wrong.

## Tests (required — this is the whole point of the ticket)

1. **Unit (`#[cfg(test)]` in `supervisor.rs`, `MockSmc`)**:
   a. mock reports `Manual` at startup ⇒ exactly one `set_mode(Auto)` issued, no other write;
   b. mock reports `Auto` ⇒ **zero** writes (no write on the healthy path);
   c. reconcile read fails ⇒ mode degrades to observe and `monitor_only` is true;
   d. reconcile restore fails (fault-injected) ⇒ mode degrades to observe, `monitor_only` true,
      and the loud error is logged.
2. **Integration (`tests/integration.rs`)**: pre-set the fixture's `fan1_manual` to `1`, spawn the
   real binary `daemon --mode observe` against `--sysfs-root <fixture>` ⇒ within one poll the
   fixture's `fan1_manual` reads `0`. Then the `--mode curve` variant ⇒ after reconcile the fixture
   shows `fan1_manual == 1` again with a real speed write (reconcile first, then take control).
3. Both tests must run **only** against fixtures — never real `/sys` (see the §8 safety block).

## CONVENTIONS (verbatim from DESIGN.md §8 — binding)

> This is a byte-faithful copy of PRD §8 as of plan time. If PRD §8 and this copy ever diverge, the PRD wins and the orchestrator re-renders from the PRD.

**Language & toolchain**
- Rust edition 2021; rustc 1.98 (Arch `extra/rust`; install via `sudo pacman -S rust` — or `pkexec --disable-internal-agent pacman -S rust` on this box).
- No async. No threads beyond the main loop (single-threaded design; `Send` bound on `Smc` is for the trait's future, not for spawning).
- Dependencies: allowlist in R11 only. Adding one = stop, record in `DEVIATIONS.md`, await planner.

**Correctness discipline**
- No `unwrap`/`expect`/`panic!` outside tests, `main.rs` wiring, and `safety.rs`'s deliberate test panic. Clippy denies them (`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` — allowlisted per-file where required).
- `unsafe` only in `safety.rs`, each block carrying a `// SAFETY:` comment naming the async-signal-safety argument.
- Every state-changing `smc` write goes through write-verify (R1). Never update logical state from an unverified write (the `mbpfan.c:410` class).
- Temps are `MilliC`, never bare `i32` across module boundaries. rpm are `u32`.

**Style**
- `cargo fmt` default config, no customization. `//!` module doc on every file stating its contract and invariants in ≤10 lines. Public items get doc comments. Safety-critical lines get `// SAFETY:` or `// INVARIANT:` comments.
- Errors: per-module `thiserror` enum; error messages name the path/key and the fix. Logging via `tracing` macros only — no `println!` outside `cli.rs` output formatting.
- Tests: unit tests co-located (`#[cfg(test)]`); cross-module tests in `tests/`. Every behavioral claim in this PRD that is testable on fixtures/mocks **must** have a test (see R10 list).

**Safety of the build process itself (non-negotiable)**
- **Never write to the real `/sys` during development.** All tests run against `tests/fixtures/sysfs/` via `--sysfs-root`. Real-hardware tests run only behind `--features hw` + `AFANCTL_HWTEST=1` + applesmc present, and only in the final supervised gate (§9). If a test would write real sysfs without those guards, that test is a bug.
- Never run the daemon against real hardware as part of ordinary development; the supervised gate does that, with the user present.
