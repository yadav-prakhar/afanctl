# F16 — fix ticket: write-verification semantics (register echo, not tach) + real fan dynamics in fixtures

Fixing a **functional defect found on real hardware** during the supervised gate. Read `DESIGN.md`
first (BINDING, see RULING F16), then `PRD.md` §6.R1 / §6.R2 / §6.R4 / §11.2-T3, then this card.

## Evidence (real hardware, 2026-09-14 20:06:19 IST, journal)

```
WARN afanctl::smc: fan1_output write not taken by hardware; retrying attempt=1 attempts=3 wrote=1200 read_back=6170
WARN afanctl::smc: fan1_output write not taken by hardware; retrying attempt=2 attempts=3 wrote=1200 read_back=5235
WARN afanctl::smc: fan1_output write not taken by hardware; retrying attempt=3 attempts=3 wrote=1200 read_back=1866
ERROR afanctl::supervisor: fan1_output 1200: verify failed: wrote 1200, read back 6170 (fallback 1/3)
ERROR afanctl::supervisor: fan1_output 1200: verify failed: wrote 1200, read back 5235 (fallback 2/3)
ERROR afanctl::supervisor: fan1_output 1200: verify failed: wrote 1200, read back 1866 (fallback 3/3)
ERROR afanctl::supervisor: L1 fallback: 3 failed writes → AUTO restored, degrading to monitor-only
```

Live registers during/after the event: `fan1_input` ≈ 5292 (tach), `fan1_output` ≈ 5290 (in Auto the
SMC mirrors its *own* target there), `fan1_manual` 0 after the fallback. The SMC's own curve had the
fan at ~6.2k rpm (its raw sensors: `TC0F` 63.5 C) while our curve commanded 1200 rpm (coretemp
`t_eff` 48–51 C). The daemon degraded to monitor-only ~2 s after `curve` was commanded.

**Fail-safe direction was correct** (AUTO restored, loud logs) — but the primary feature does not
work on real hardware.

## Root cause (verified in source, not inferred)

1. `src/smc.rs:327-357` — `SysfsSmc::write_speed` writes `fan1_output` and then verifies against
   **`fan1_input`** (line 339, `read_u32(&input)`). `fan1_input` is the *tachometer*: it lags an
   arbitrary distance behind a command and only equals the target after the fan has settled. Any
   command differing from the current tach by more than 150 rpm is therefore reported as "write not
   taken" — unavoidably during every ramp, and instantly whenever we take over from a fast-spinning
   SMC fan.
2. `src/supervisor.rs:514-600` — `l1_poll` treats that same physical deviation
   (`fan.rpm.abs_diff(written) > VERIFY_TOLERANCE_RPM`) as a **write failure** and, after
   `WRITE_FAIL_FALLBACK = 3` consecutive polls, restores AUTO and **latches monitor-only**.

Combined effect: curve mode disables itself the moment the target moves more than 150 rpm from the
actual fan speed — i.e. during every transition. Invisible on fixtures because `MockSmc` and the
fixture tree echo a write into `fan1_input` **instantly** (idealized physics: command == tach). That
is why 126 tests and the adversarial review all passed.

## RULING F16 (frozen — implement exactly; `DESIGN.md` amended by the orchestrator)

- **R1 — echo verification.** Verifying a `fan1_output` write means reading back **`fan1_output`**
  and comparing it with what we wrote, tolerance `WRITE_ECHO_TOLERANCE_RPM = 50`. This is the
  "was the write taken" check (the mbpfan H6/M8 silent-write-failure class). **`fan1_input` is never
  a write-verification source.**
- **R2 — physical convergence is not a failure.** Split `l1_poll` into two independent checks:
  - **Mode drift**: the fan reads `Auto` while we believe we own it ⇒ re-assert `set_mode(Manual)`
    through the verify path. Only mode-drift failures, write syscall errors and echo failures
    increment `write_failures` (→ `WRITE_FAIL_FALLBACK` → AUTO + monitor-only). Genuine fault: another
    agent seized the fan, or the register will not take our value.
  - **Tracking**: while `manual_armed` and the command is unchanged, if
    `|actual − last_written| > VERIFY_TOLERANCE_RPM`, re-issue the write (idempotent re-assert).
    **Do not count it as a failure** — a fan that is still decelerating is not a broken fan.
- **R3 — stall detector** (keeps the safety intent without the false positives): if the *command* has
  been unchanged for `STALL_POLLS = 10` consecutive polls **and** `|actual − command|` is still
  `> VERIFY_TOLERANCE_RPM` **and** has not decreased over that window ⇒ the actuator is not
  responding ⇒ log an error, count a failure ⇒ AUTO + monitor-only.
- **R4 — constants.** `WRITE_ECHO_TOLERANCE_RPM = 50` and `STALL_POLLS = 10` live with the other
  safety tunables (`policy.rs` / `supervisor.rs` consts, **not** config, R6). `VERIFY_TOLERANCE_RPM = 150`
  keeps its meaning as the steady-state tracking band.
- **R5 — fixtures must model reality.** `MockSmc` (and any rpm-modelling fixture backend) gains a
  **tach-lag mode**: actual rpm slews toward the commanded target at a bounded rate (default
  ≤ 1500 rpm/s), so a command far from the current speed takes several seconds to be reached. The
  fixture tree should also mirror the SMC's *own* value into `fan1_output` while in Auto (real
  applesmc does — see the evidence above), so an echo check while not in manual is correctly seen as
  "not taken". Keep the existing instant-echo behavior available, but the new tests below must use
  lag mode.

## Required tests

## CONVENTIONS (verbatim from DESIGN.md §8 — binding)

> This is a byte-faithful copy of PRD §8 as of plan time. If PRD §8 and this copy ever diverge, the PRD wins and the orchestrator re-renders from the PRD.

**Language & toolchain**
- Rust edition 2021; rustc 1.98 (Arch `extra/rust`; install via `sudo pacman -S rust` — or `pkexec --disable-internal-agent pacman -S rust` on this box).
- No async. No threads beyond the main loop (single-threaded design; `Send` bound on `Smc` is for the trait's future, not for spawning).
- Dependencies: allowlist in R11 only. Adding one = stop, record in `DEVIATIONS.md`, await planner.

**Correctness discipline**
- No `unwrap`/`expect`/`panic!` outside tests, `main.rs` wiring, and `safety.rs`'s deliberate test panic. Clippy denies them (`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` — allowlisted per-file where required).
- `unsafe` only in `safety.rs`, each block carrying a `// SAFETY:` comment naming the async-signal-safety argument.
- Every state-changing `smc` write goes through write-verify (R1). Never update logical state from an unverified write (the `mbpfan.c:410` class).
- Temps are `MilliC`, never bare `i32` across module boundaries. rpm are `u32`.

**Style**
- `cargo fmt` default config, no customization. `//!` module doc on every file stating its contract and invariants in ≤10 lines. Public items get doc comments. Safety-critical lines get `// SAFETY:` or `// INVARIANT:` comments.
- Errors: per-module `thiserror` enum; error messages name the path/key and the fix. Logging via `tracing` macros only — no `println!` outside `cli.rs` output formatting.
- Tests: unit tests co-located (`#[cfg(test)]`); cross-module tests in `tests/`. Every behavioral claim in this PRD that is testable on fixtures/mocks **must** have a test (see R10 list).

**Safety of the build process itself (non-negotiable)**
- **Never write to the real `/sys` during development.** All tests run against `tests/fixtures/sysfs/` via `--sysfs-root`. Real-hardware tests run only behind `--features hw` + `AFANCTL_HWTEST=1` + applesmc present, and only in the final supervised gate (§9). If a test would write real sysfs without those guards, that test is a bug.
- Never run the daemon against real hardware as part of ordinary development; the supervised gate does that, with the user present.
