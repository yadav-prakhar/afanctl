## RULING F21 (frozen — implement exactly)

### R1 — the observe transition must not drop ownership on a failed release (MAJOR)

`apply_mode`'s observe branch (`requested == Observe && mode != Observe`) on `set_mode(FanMode::Auto)`
error currently does `self.manual_armed = false` — i.e. it declares the fan released when it is still in
Manual. Everything downstream then goes blind: `l1_poll` early-returns "not ours to verify" (no
mode-drift, tracking, stall or dwell checks), `act()` writes nothing, nothing ever retries AUTO, and the
cmd freshness gate suppresses re-applying the same observe command. The fan sits in Manual at the last
speed with the state rendering healthy. This is exactly the shape RULING F20 R2 fixed in
`degrade_to_auto`; the observe branch was missed. Reproduced live (probe B).

Required, mirroring R2:
- On `Err`: **keep `manual_armed = true`**, set `auto_restore_pending = true` (and
  `auto_restore_attempts = 1`, with the log-rate-limit counter armed), record the truthful message in
  `recent_errors`, and **do not** claim the mode applied successfully.
- The mode field still becomes `Observe` (that is the requested intent and it stops speed commands), but
  ownership and the pending flag tell the truth until the release actually verifies.
- The existing every-poll `auto_restore_retry` then completes the release as soon as it can, clearing the
  flag with the `"AUTO restored after N attempts"` note.
- On `Ok`: unchanged (clear `manual_armed`, clear any pending flag, note `cmd applied: observe`).

### R2 — restore the watchdog margin (the settle window cost it)

`settle()` blocks up to ~1.35 s per failing window (9 × 150 ms) and `WRITE_RETRY_MAX = 1` doubles it:
≈2.7 s per failing `write_speed`, ≈1.8 s per failing `set_mode`. With `WatchdogSec=15` and a ping only at
the end of `step_once`, a *healthy* curve poll at the legal `interval_s = 14` blocks ≈0.15–1.05 s on a
changed target, pushing the ping gap to ≈15.0–15.5 s — past the watchdog, so a legal config SIGABRT-crashes
a healthy daemon into a restart loop exactly in the oscillating-temperature regime curve mode exists for.
(`interval_s = 1` is safe: worst poll ≈7.2 s, gap ≈8.2 s, ~45 % margin.)

Required:
- **Ping the watchdog twice per poll**: at the start and at the end of `step_once` (two `WATCHDOG=1`
  notifications), so a long poll cannot extend the gap beyond `max(interval, poll_work)`.
- **Lower the cap**: `config::MAX_INTERVAL_S` 14 → **12**, with the reasoning in the doc comment
  (worst-case poll work ≈2.7 s; 12 + the poll's own blocking keeps ≥3 s margin under the 15 s watchdog).
  Update whatever README/prose states the 14 s cap so docs match.

### R3 — R4 visibility: the off-target dwell WARN must repeat

`off_target_warned` latches, so a permanently off-target, low-movement fan gets **one** WARN and then
silence for the daemon's lifetime (proven, probe A). The stall criterion stays as ruled, so visibility is
the fix: drop the latch and re-warn **every** `OFF_TARGET_WARN_POLLS = 30` polls while the excursion
persists (≈ one line per 30 s at default cadence), with the poll count in the message and a
`recent_errors` entry per warning. Reset only on convergence (within tolerance) or degradation. Document
the trade-off in the code comment and in the README: the stall detector keys on *any* tach movement, so a
fan that jitters above `STALL_TACH_EPSILON_RPM` while parked off target is reported (repeatedly), not
degraded — deliberate, because a per-poll criterion cannot separate "jittering but never converging" from
"healthily chasing without converging yet".

### R4 — pin what the reviews keep finding unpinned (MINOR 4–7)

- Pin the F19/F20 constants by value in `tests/pin_constants.rs`: `ECHO_SETTLE_MS = 1500`,
  `ECHO_SETTLE_SAMPLES = 10`, `MODE_SETTLE_MS = 1000`, `WRITE_RETRY_MAX = 1`, `STALL_TACH_EPSILON_RPM = 50`,
  `AUTO_RETRY_LOG_POLLS = 10`, `OFF_TARGET_WARN_POLLS = 30`, `MAX_INTERVAL_S = 12`. Where a value has a
  behavioural consequence, pin that too (e.g. a 26-rpm-jitter-while-off-target case ⇒ motionless ⇒ the
  window fills; a 60-rpm-jitter case ⇒ no stall but a *repeating* WARN). These two tests make the
  trade-off intentional and pinned rather than incidental.
- Pin the **every-poll** AUTO retry: a variant that retries only on alternate polls must fail a test
  (today it passes).
- Pin the repeating-warn semantics (finding 7): a re-latching (once-per-excursion) implementation must
  fail a test.
- `README.md:21-22`: the clause "never moves **toward** its command" is wrong — the detector keys on
  movement *between polls*. Fix the clause and describe the repeating dwell WARN.
