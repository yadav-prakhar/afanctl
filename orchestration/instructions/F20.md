# F20 — fix ticket: close the two MAJOR holes T9b proved (stall window defeated by a moving command; failed-AUTO fallback strands a Manual fan)

Both findings were reproduced live by the T9b reviewer against fixture copies and **re-verified in
source by the orchestrator** (`src/supervisor.rs:593-608` and `648-680`). Read `DESIGN.md` first
(BINDING, see RULING F20 — the constants list is already updated there), then
`orchestration/REVIEW-T9b.md` (findings 1–9 with reproduction detail), then this card.

The old (pre-F16) code caught both of these; F16's split removed its over-eager counting, and these
two holes are what replaced it. Closing them without re-adding the false positives is the whole task.

## RULING F20 (frozen — implement exactly)

### R1 — stall detector keyed to **tach movement**, not to command changes (MAJOR 1)

Today the window resets whenever the written target changes (`stall_cmd != Some(written)`) and also on
any deviation dip. During curve slew — or a mid-band temperature oscillation — the command changes every
poll, so the window never reaches `STALL_POLLS` and a **frozen fan is never declared** while temps
oscillate (repro: 38 polls, `verified: true`, `monitor_only: false`, empty `recent_errors`, dead fan).

Replace the criterion with: while `manual_armed` and `dev = |actual − command| > VERIFY_TOLERANCE_RPM`,

- a poll counts as **progress** if the tach moved at all since the previous poll
  (`|actual − prev_actual| > STALL_TACH_EPSILON_RPM = 50`) or the fan is now within tolerance;
- otherwise `stall_polls += 1`; **a command change must not reset anything**;
- fire when `stall_polls >= STALL_POLLS` (10) and still off-target.

Rationale: a real fan's tach always moves when commanded somewhere else — measured on this hardware:
6688 → 2664 → 1632 → … → 2001 within ~5 s, ±20 rpm at rest. A dead/disconnected/frozen actuator has a
constant tach. Keying on movement is therefore insensitive to a moving command *and* to mid-band
oscillation, and cannot be defeated by either. Keep N-F16-1's direct degrade (no 3-strike ladder) and
keep the tracking re-assert uncounted (RULING F16 stands).

### R2 — a failed AUTO restore must not be silent, must be re-attempted, and must not lie (MAJOR 2)

`degrade_to_auto` currently sets `manual_armed = false` **even when its own `set_mode(Auto)` failed**,
which switches L1 off for the mode check and (with `monitor_only`) stops every write — so a fan left in
Manual stays there, unsupervised, with nothing re-attempting AUTO, and the success message
`"L1 fallback: 3 failed writes → AUTO restored, degrading to monitor-only"` is printed **even on
failure**. A plugin that honours `monitor_only` by going quiet then strands the fan forever.

Required:
- Commit the success path only on `Ok`: `manual_armed = false`, the "AUTO restored" message, clear any
  pending flag.
- On `Err`: keep `manual_armed = true` (we still own the fan), set a new `auto_restore_pending` flag,
  log the **truthful** message, and record it in `recent_errors`.
- While `auto_restore_pending`: make one best-effort `set_mode(FanMode::Auto)` attempt per poll, and
  rate-limit the log to once every `AUTO_RETRY_LOG_POLLS = 10` polls (an ERROR naming the attempt count
  and that the fan is still Manual). On the first success: clear the flag, log
  `"AUTO restored after N attempts (fan1_manual=0, verified)"`, note it.
- While `auto_restore_pending`, do **not** re-assert Manual on mode drift (we are trying to release the
  fan); if the register reads `Auto`, treat that as success.
- Never stop retrying, and never claim success without a verified read-back.
- Expose it: additive `auto_restore_pending: bool` in `afanctl.state.v1` **and** in the `daemon` object
  of `afanctl.status.v1`, plus a human `status` marker (`(AUTO restore pending)`); schema ids unchanged,
  additive-only (F18 precedent). A plugin must be able to tell this state from a healthy one.

### R3 — the "no L2 → observe" invariant must hold on every channel (MINOR 3)

`run()` degrades the startup mode to observe when `panic_fd().is_none()`, but `apply_mode` re-arms
control from `cmd.json` without that check (proven live: `l2_armed=false` yet control entered). Make
`apply_mode` refuse writing modes (`curve`/`hold`) when `panic_fd().is_none()`: log an error, stay in
observe, record it in `recent_errors`. One invariant, both channels.

### R4 — off-target dwell must be visible (MINOR 4)

A fan hovering just outside `VERIFY_TOLERANCE_RPM` with a moving tach legitimately never trips the
stall detector, but it should not be invisible: count `off_target_polls` while armed and off-target;
when it first crosses `OFF_TARGET_WARN_POLLS = 30`, emit one WARN + `recent_errors` entry
(`"fan X rpm off target for 30 polls (moving, not stalled)"`), once per excursion. No degradation.

### R5 — docs and pinned values (MINORS 5–9)

- `README.md` L1 paragraph: reword to the F16/F20 semantics — a tracking deviation is re-asserted and
  **never counted**; only mode-drift failures, write errors and echo failures feed the 3-strike ladder;
  say what the stall detector keys on now.
- `README.md`: one sentence documenting that the startup reconcile takes the fan from **any** Manual
  owner, including a foreign program (mbpfan) — deliberate, RULING F14.
- Pin the frozen constants with tests that fail if the value changes: echo tolerance boundary (a
  read-back 49 rpm off passes, 51 rpm off fails), and the stall detector firing at exactly
  `STALL_POLLS` polls — not "within".
- Add a test asserting the **startup evidence line** fields, including `config_source` (no test
  covers it today, so it can silently regress).

## CONVENTIONS (verbatim from DESIGN.md §8 — binding)

> This is a byte-faithful copy of PRD §8 as of plan time. If PRD §8 and this copy ever diverge, the PRD wins and the orchestrator re-renders from the PRD.

**Language & toolchain**
- Rust edition 2021; rustc 1.98 (Arch `extra/rust`; install via `sudo pacman -S rust` — or `pkexec --disable-internal-agent pacman -S rust` on this box).
- No async. No threads beyond the main loop (single-threaded design; `Send` bound on `Smc` is for the trait's future, not for spawning).
- Dependencies: allowlist in R11 only. Adding one = stop, record in `DEVIATIONS.md`, await planner.

**Correctness discipline**
- No `unwrap`/`expect`/`panic!` outside tests, `main.rs` wiring, and `safety.rs`'s deliberate test panic. Clippy denies them (`clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` — allowlisted per-file where required).
- `unsafe` only in `safety.rs`, each block carrying a `// SAFETY:` comment naming the async-signal-safety argument.
- Every state-changing `smc` write goes through write-verify (R1). Never update logical state from an unverified write (the `mbpfan.c:410` class).
- Temps are `MilliC`, never bare `i32` across module boundaries. rpm are `u32`.

**Style**
- `cargo fmt` default config, no customization. `//!` module doc on every file stating its contract and invariants in ≤10 lines. Public items get doc comments. Safety-critical lines get `// SAFETY:` or `// INVARIANT:` comments.
- Errors: per-module `thiserror` enum; error messages name the path/key and the fix. Logging via `tracing` macros only — no `println!` outside `cli.rs` output formatting.
- Tests: unit tests co-located (`#[cfg(test)]`); cross-module tests in `tests/`. Every behavioral claim in this PRD that is testable on fixtures/mocks **must** have a test (see R10 list).

**Safety of the build process itself (non-negotiable)**
- **Never write to the real `/sys` during development.** All tests run against `tests/fixtures/sysfs/` via `--sysfs-root`. Real-hardware tests run only behind `--features hw` + `AFANCTL_HWTEST=1` + applesmc present, and only in the final supervised gate (§9). If a test would write real sysfs without those guards, that test is a bug.
- Never run the daemon against real hardware as part of ordinary development; the supervised gate does that, with the user present.

- Ambiguity or a blocking question → write it to `QUESTIONS.md`, continue with the unambiguous remainder, and say so in your summary. Do not invent spec.
